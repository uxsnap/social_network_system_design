# System Design социальной сети для курса по System Design

## Функциональные требования

Пользователь может:

1. Публиковать посты (прилагать фото, описание, место путешествия)
2. Оценивать посты (система лайков, комментарии)
3. Просматривать ленту (собственную ленту, ленту других путешественников)
4. Искать популярные места для путешествий
5. Просматривать посты с мест путешествий
6. Подписываться на других путешественников для просмотра их активности

## Нефункциональные требования

1. Количество пользователей в день (DAU) = **10 000 000**
2. Availability = 99.95p
3. Сезонность есть (на праздники, приуроченные к сезоны, например Новый Год)
4. Availability over Consistency (данные не должны теряться)
5. Расчет нагрузки идет на 5 лет вперед
6. Аудитория - пользователи с СНГ

### Активность пользователей:

Пользователь в среднем будет:

1. Делать **1** пост в день
2. Просматривать ленту **5** раз в день
3. Детально просматривать пост **2** раза в день
4. Ставить **15** лайков в день
5. Читать **20** комментариев в день
6. Оставлять **2** комментария в день
7. Делать **3** поиска в день

Лимиты:

1. У пользователя может быть неограниченное количество подписчиков
2. Пользователь максимум может подписаться на **100 000** человек
3. Длина комментария - 140 символов
4. Пользователь может ставить неограниченное количество лайков
5. Длина описания поста - 280 символов

Временные ограничения:

1. Пользователь должен видеть новый пост в своей ленте не более чем через 10 секунд после публикации
2. Пользователь должен видеть оставленный комментарий не более чем через 5 секунд после публикации
3. Поиск должен находить первые результаты через 1-2 секунды
4. Подписка - мгновенно
5. Загрузка расширенного поста - до 5 секунд (учитываем фото)

## Расчет нагрузки приложения

Connections = 10 000 000 \* 0.1 = 1 000 000

### Подсистема постов

1. Создание поста = 10 000 000 \* 1 / 86 400 ~ 115
2. Просмотр поста = 10 000 000 \* 2 \* 3 \* 5 / 86 400 ~ 3472

### Подсистема оценок

1. Добавление комментария = 10 000 000 \* 2 / 86 400 ~ 230
2. Оценка поста = 10 000 000 \* 15 / 86 400 ~ 1736

### Подсистема поиска

1. Совершать поиск локаций = 10 000 000 \* 3 / 86 400 ~ 347

## Расчет трафика

### Подсистема постов

Размер поста = 280B \* 2 (на территории СНГ) + 2048B (длина ссылки S3) + 5KB (метаданные) ~ 7.6 KB

1. Создание поста = 115 RPS \* 5МБ (размер фото) = 575 MB/s
2. Просмотр поста = 3472 RPS \* 7.6 KB (размер фото, пользователь будет запрашивать фото с S3 напрямую) ~ 25.76 MB/s

### Подсистема оценок

1. Добавление комментария = 230 RPS \* (560B + 5KB) ~ 1.246 MB/s
2. Оценка поста = 1736 RPS \* ( 8B(ID поста) + 5KB) ~ 8.49 МB/s

### Подсистема поиска

1. Совершать поиск локаций = 347 RPS \* 200B ~ 0.07 MB/s

## Оценка дисков

### Подсистема постов

Traffic: 575 MB/s + 25.76 MB/s ~ 601 MB/S

Сapacity = 601 МБ/с \* 86 400 \* 365 = 18 PB/year
Disks_for_capacity = 3 ТБ / 2 ТБ = 1.5
Disks_for_throughput = 110 МБ/с / 100 МБ/с = 1.1
Disks_for_iops = 300 / 100 = 3
Disks = max(ceil(1.5), ceil(1.1), ceil(3)) = 3
